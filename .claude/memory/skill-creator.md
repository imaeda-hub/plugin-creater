# Anthropic の skill-creator

Anthropic が公開している、スキルを作って改善するスキル。2026年10月に、クラウド環境に入っている版（`/mnt/skills/examples/skill-creator/`）の全ファイルを読んで分かったこと。クリエイターの仕様では、質問の項目の出どころの1つにしている（[作る流れの要件](../../docs/specs/creation-requirements.md) REQ-015、REQ-017）。

## 流れ

1. 何をするスキルかを聞く。聞くのは、何をするか、いつ呼ばれるか、出力の形、試験をするかの4つと、例外的な場合・成功の基準・依存するもの。会話の中にすでに手順があれば、そこから先に読み取る。
2. `SKILL.md` の下書きを書く。
3. 試す課題を2〜3個作り、スキルあり・なし（直すときは前の版）で、サブエージェントを同時に動かす。
4. 動いているあいだに採点の基準を書く。終わったら採点し、結果を見る画面を開いて、ユーザーに見てもらう。
5. ユーザーの感想をもとに直し、3に戻る。ユーザーが満足するか、感想がなくなるまで繰り返す。
6. 最後に、スキルの説明文（description）を、呼ばれ方の試験で直す。

「試験はいいから一緒に作って」と言われれば、試験を省く。下書きを持ってきた人には、3から始める。

## 取り入れる価値のある仕組み

| 仕組み | 内容 |
| --- | --- |
| 結果を見る画面 | 課題ごとに出力を並べ、感想を書く欄がある。2回目からは、前回の出力と前回の感想が横に出る。感想は `feedback.json` に保存され、次の直しに使う。Excel・PDF・画像もその場で見られる。画面を開けない環境では、1つの HTML ファイルに書き出す |
| 呼ばれ方の試験 | 呼ばれるべき依頼と、呼ばれてはいけない紛らわしい依頼を、8〜10件ずつ作る。紛らわしい依頼ほど価値がある（関係のない依頼では試験にならない）。ユーザーが画面で直す。依頼ごとに3回試し、呼ばれた割合で合否を出す。依頼の6割で説明文を直し、残りの4割の成績で一番よい説明文を選ぶ（手元の例に合わせすぎないため）。最大5回直す |
| 採点者が試験も批評する | 採点のサブエージェントは、合否のほかに、試験の弱いところを指摘する。間違った成果物でも通る基準、だれも見ていない大事な結果、確かめようのない基準などである。合格させる根拠がないときは不合格にする |
| 差のつかない基準を見つける | あり・なしの結果を並べ、どちらでも通る基準（スキルの効果を測れていない）や、結果がばらつく課題を洗い出す |
| どちらの版か伏せた比べ合い | 2つの出力を、どちらの版か伏せたまま別のエージェントに比べさせ、そのあとで勝った理由を分析する |
| 繰り返し出てくる処理をスクリプトにする | 試験の記録を読み、どの課題でもエージェントが同じ補助スクリプトを書いていたら、スキルに入れる |

## 気をつけること（読んで見つけた問題）

- 手順書が指示する結果のフォルダ（`eval-0/with_skill/outputs/`。名前は内容が分かるものにする、とも書いてあり、食い違う）と、集計スクリプトが探すフォルダ（`eval-*/<設定>/run-*/grading.json`）が合わない。手順書どおりにすると、集計が空になるおそれがある。
- 呼ばれ方の試験は、依頼の数 × 3回 × 最大5回、`claude -p` を動かす（20件なら最大300回）。前もって費用の見込みを示したり、承認を求めたりはしない。
- 呼ばれ方の試験では、本物のスキルではなく、プロジェクトの `.claude/commands/` に一時的なコマンドのファイルを置き、それが読まれたかで判定する。本物のスキルの呼ばれ方とずれる可能性がある。
- 結果を見る画面を開くとき、使いたい番号（3117）を使っているほかのプロセスを止める。
- 試験の課題（`evals/`）は、配る `.skill` ファイルから除かれる。受け取った人の手元には、フロントマターの形式の検査しか残らない。

## クリエイターとの違い

- skill-creator は、作るのは軽く、試して直すことに重きを置く。クリエイターは、ナレッジを引き出すことと、引き出したナレッジが確実に入ること、渡した後に保守できることに重きを置く。
- skill-creator の聞き取りの手順は短い。質問の良し悪しを測る仕組み（クリエイターの外側の EVAL に当たるもの）はない。
- skill-creator の結果を見る画面には入力の欄がある。クリエイターの画面は見るだけにしている（REQ-043）。
