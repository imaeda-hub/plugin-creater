# Claude Code の EVAL の仕組み

Claude Code のプラグインの EVAL（`claude plugin eval`）の仕組み。2026年10月時点の公式ドキュメントによる。

## 流れ

1. `claude plugin eval init`：対話しながら、課題と採点の条件を作る。
2. `claude plugin eval .`：課題を実行して、採点する。

## 課題と採点

- 課題は、ユーザーが打ちそうな依頼文と、1つ以上の採点（グレーダー）でできている。
- 既定では、課題ごとに、プラグインありで3回、なしで3回実行する。ありのスコア（WITH）、なしのスコア（W/OUT）、その差（Δ）が出る。差がプラグインの効果である。
- 採点の種類：

  | 種類 | 合格の条件 |
  | --- | --- |
  | `regex` | 返答や作ったファイルに、正規表現に合う文字列がある |
  | `tool_used` | 決まったツール（スキルの呼び出しを含む）を使った |
  | `tool_order` | ツールを決まった順に使った |
  | `file_exists` | 決まったファイルを作った |
  | `llm` | 別のモデルが、採点の基準に沿って合格と判定した。画像も読める |
  | `baseline` | 手本の記録と比べて、同じくらい良いと別のモデルが判定した |

- プログラムで採点する種類はない。

## 実行の環境

- 実行のたびに、一時的なホーム・作業フォルダ・設定で始め、試すプラグインだけを読み込む。
- 会話の続きは、記録した会話（`history_file`）で与えられる。ユーザー役が質問に答える仕組みは、ドキュメントに見当たらない。
- Bash を使う課題には、OS のサンドボックスが要る。Linux では bubblewrap と socat を入れる。
- 実行もモデルによる採点も、モデルを使うので、利用量や費用がかかる。
