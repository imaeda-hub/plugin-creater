# クリエイターのエクステンションのツールの説明の文（案）

B3 が R1 に沿って書いた、`com.github.copilot/extensions/plugin-creator/descriptions.mjs` の【仮】の文に替える案である。C1 が descriptions.mjs に入れる（B3 はそのファイルを変えない）。

書き方の決まり（R1）：何をするツールかと、いつ呼ぶかを書く。強い言葉を使わず、理由が要るところだけ短く添える。ツールの定義は毎回モデルに送られるので、短くする。段階・項目・状態の名前は、画面に出る日本語の名前のままにする（BLUEPRINT 7章）。

## TOOL_DESCRIPTIONS

| ツール | 説明の文 |
| --- | --- |
| `open` | plugin-creator の画面（お話で決まったことの一覧、生成前の確認で示すもの、試験の結果を見るブラウザーの画面）を起動し、URL を返す。make-plugin と test-plugin の始めに呼び、返った URL をチャットで示す。画面は見るだけで、答えはチャットで受ける。 |
| `state` | ヒアリングの記録（今の段階、項目ごとの状態、確かめていない候補、保留と AI の判断、画面の URL、セッションの番号、記録のファイルの場所）を返す。コンパクションの後、再開の後、段階の始めに、まず呼ぶ。止まっている画面は起動し直す。 |
| `progress` | 今の段階と、項目の状態（聞いた、決まりなし、保留）を記録する。項目の状態を変えるときは、ユーザーの言葉の短い抜き書きを添える。段階を「生成」に進めるのは、`plugin-creator_confirm` が受け付けられ、ユーザーが作ってよいと答えた後だけで、そのときは答えの抜き書きを添える。 |
| `record` | ヒアリングで分かったナレッジ（仕事のやり方や決まり）、流用する資産、標準機能と公開のプラグインの選んだ結果を記録する。ユーザーの答えを受けたら、次の問いの前に呼ぶ。会話の中の答えは、コンパクションで消えるためである。新しいナレッジには番号（K-01 など）が付く。番号を渡すと、そのナレッジを直せる。 |
| `confirm` | 生成前の確認で示すもの（決まったナレッジの番号、振る舞いの案、作業の定義の案の場所、EVAL の課題と基準）を受け取り、plugin-creator の画面に出し、Web管理画面の見本の URL を返す。未着手の項目が残っているときは受け付けない。示した内容を直したら、呼び直す。 |
| `results` | 試験の結果のファイル（`tests/results/latest.json` と EVAL の結果）の場所を受け取り、plugin-creator の画面に出す。試験が終わったら呼ぶ。 |
| `doc_text` | docx・xlsx・pptx の中の文字を返す。ファイルの読み取りのツールでは、これらの文書の中の文字を読めないので、その代わりに使う。 |
| `issue` | 質問の改善案を、plugin-creator のリポジトリ（imaeda-hub/plugin-creator）に Issue として起票する。ユーザーが、その案を起票してよいと答えた後にだけ、1案ずつ呼ぶ。題と本文には決まった言葉（段階と項目の名前、起きたことの種類、数、問いの形、版、モデル）だけを書き、ユーザーの仕事の中身（問いの文、答え、ナレッジの文、ファイル名）を書かない。 |

## PARAM_DESCRIPTIONS（今の仮の文から変えるものだけ）

| ツール | 引数 | 説明の文 |
| --- | --- | --- |
| `progress` | `approvalQuote` | 段階を「生成」に進めるときだけ渡す。作ってよいというユーザーの答えの抜き書き。 |
| `record` | `knowledge.status` | ナレッジの状態。ファイルや頼みの文から推し量っただけで、まだユーザーが確かめていないものは「候補」。ユーザーが答えたもの、確かめたものは「決まった」。確かめて違ったものは「外した」。 |
| `record` | `knowledge.item` | ナレッジの項目。10項目（作業の目的、頼む場面と言い方、受け取るもの、進め方、成果物、合否の決め方、決まった書き方やルール、守らないと困ること、使う道具と環境、いつもと違うとき）のどれか。 |
| `record` | `assets.status` | 資産の状態。まだ決めていないものは「候補」、使うと決まったものは「流用する」、使わないものは「流用しない」。 |
| `confirm` | `taskPath` | 作業の定義の案の絶対パス。作業フォルダの `.plugin-creator-work/draft/task.json`。 |
| `confirm` | `evalTasks.criteria` | 課題の合否の基準にするナレッジの番号の一覧。種類が「合否の決め方」のナレッジだけを入れる。 |
| `issue` | `title` | Issue の題。決まった言葉だけで、1行で書く。 |
| `issue` | `body` | Issue の本文。決まった言葉だけで書き、ユーザーの仕事の中身を書かない。 |

## 返り値の文について（C1 への引き継ぎ）

- 状態取得ツールの「確かめていない候補」の行に、出どころ（「ファイルから読んで確かめた」などの名前）を足してほしい。make-plugin の段階「決まりの確かめ」は、出どころがファイルか既存のプラグインの候補だけを確かめるので、コンパクションの後に見分けるのに要る（references/rules.md）。
