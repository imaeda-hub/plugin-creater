## 決めたこと

設計書と R2 が決めていない細かいところを、設計書の目的に合う最も単純な形にした。

**構造**
- `adapter.mjs` は `startAdapter({ joinSession })` を出す。プラグインの根は adapter.mjs 自身の場所（`extensions/<名前>/`）の3つ上。名前は根の `plugin.json` の `name`（読めない・name がないときは、セッションに加わる前に平易な日本語で失敗）。`extension.mjs` は SDK の `joinSession` を読み込んで渡すだけ（7行）。SDK の import は extension.mjs にだけ置く。標準出力には書かない（調べるための出力は console.error）。
- 返り値は `{ pluginName, pluginRoot, dataRoot, session, port, core, shutdown }`（試験が使う）。本体に試験のための引数・環境変数・出口は足していない。
- ツールの定義は、`core.toolDefinitions` と同じ `buildToolDefinitions(pluginName)`（core/tools.mjs）で作る。`joinSession` の時点でツールを渡す必要があるが、core は session ができた後（port・セッションの番号・作業フォルダが要る）にしか作れないため。ハンドラーは core ができるまで待つ（ごく短い間）。core を作れなかったら、起動が失敗し、待っていた呼び出しも失敗する。フックは core ができる前は通す、許可の求めの受け口は no-result。
- 作業フォルダは `session.rpc.workspaces.getWorkspace()` の `workspace.cwd`。取れないときは `process.cwd()`。COPILOT_HOME は `process.env.COPILOT_HOME`、なければ `~/.copilot`。記録の置き場所は `<COPILOT_HOME>/plugin-data/<名前>/runs/`。
- 終わり方：SIGTERM・SIGINT を受けたら、イベントの受け取りをやめ、受け口を外し、`core.shutdown()`（画面のサーバーを閉じる）を呼んでから `process.exit(0)`。`shutdown()` は何度呼んでも1回だけ。失敗は飲み込んで標準エラーに残す。受け口は core ができた後に登録する（それまでは Node の既定どおり、すぐ終わる）。

**ツールの登録**
- 記録のツールは全部 `defer: 'never'` で登録する（ツール検索の裏に回さない）。SDK の型：`defer` は `"auto" | "never"`、既定は `"auto"`で、`auto` だとツールが多いとき裏に回されうる（R2 の 3.3）。C1 のクリエイターのエクステンションも `never`。open だけでなく全部にしたのは、統括・作業・検証が `plan` などを呼べなくなるほうが害が大きく、先に読み込む費用（ツールの説明の文）は小さいため。メインのエージェントに、使わない記録のツールの説明も常に載る費用がある。

**画面を開くツールの返り値**（モデルが読み、ユーザーに伝える文。B2 の入口のスキルが前提にする形）
```
Web管理画面の URL：http://127.0.0.1:<番号>/?k=<合言葉>

ユーザーに伝えてください：
- 実行中は /clear を使わないでください。…（core の CLEAR_NOTICE）
- 実行中にエージェントが確認…（core の CHAT_CONFIRM_NOTICE）
- （前の実行が途中で終わっていたときは、その知らせ）
```
記録のツールの断りは、例外を投げず、失敗の結果で返す（下の「V1 の直し」。最初の版は例外を投げていたが、実機ではモデルに理由が届かなかった）。

**イベントの直し方**（BLUEPRINT 3.1。偽物の SDK の試験で確かめた）
- 時刻 `at` は、イベントの `timestamp` のミリ秒。読めなければ受け取った時刻。
- `agent.started`：`parentAgentId` は `data.parentId`（イベントの `parentId` は1つ前のイベントなので使わない）、`description`（画面の枠の「担当」）は下記、`agentType` は `<プラグイン>:<エージェント>` にそろえる。そろえ方：`data.agentType`、なければ `data.agentName` の順に見て、すでに `<プラグイン>:` つきならそのまま、名前だけで `agents/<名前>.agent.md` がこのプラグインにあるものは頭を足す、ほかのエージェント（explore など）はそのまま。
- 「担当」（`description`）：下の「V1 の直し」のとおり、統括の task 呼び出しの description を `toolCallId` で結んで使う。見つからないときは、親のあるエージェント（作業・検証）に `agentDisplayName`（空白だけなら使わない）、なければ `agentDescription` を付ける。（型の説明は「agentDisplayName が呼び出しの説明」だったが、実機では短い名前だった。）親のない統括（`tasks.startAgent` で起動。`agentDisplayName` は起動のときに渡した名前の「統括 <実行の番号>」）には付けない。core は統括の担当を、頼まれた作業の要約で持っていて、`description` が来ると上書きするため。
- `agent.completed`：`cancelled`、`response`。`response` は `onSubagentStop` フックの `response` を `agentId` で覚えておき、終わりのイベントで1回だけ使う（フックが終わりのイベントより先に届く前提）。フックは何も返さない（`block` を返すと子の動きを変える）。
- `agent.idle`：`system.notification` の `kind.type === 'agent_idle'` のときだけ。番号は `kind.agentId`。
- `tool.started` に `arguments` をつける。`tool.completed` の `toolName` は、終わりのイベントにないので、開始のイベントから `toolCallId` で覚えて補う（なければ「不明なツール」）。`error` は `error.message`。
- 待ち：`permission.requested` → `wait.started`（kind は permission）。`detail` は `permissionKind`（求めの kind）、`toolKind`（mcp は `<サーバー>/<ツール>`、custom-tool・hook はツール名、ほかは kind）、shell は `command`（全文）・`paths`（possiblePaths）・`urls`（possibleUrls の url）・`warning`、write は `paths`（fileName）、read は `paths`（path）、url は `urls`、`sandboxPermissive`（requestSandboxPermissive）、`sandboxBypass`（requestSandboxBypass && !requestSandboxPermissive）。`resolvedByHook` を渡す。エクステンション自身の権限の求めも、種類を `permissionKind` に入れて渡す（出さないのは core）。`user_input.*` → question（`detail.question`）、`session_limits_exhausted.*` → limit。`*.completed` → `wait.ended`（limit は `action`）。`requestId` がない待ちのイベントは渡さない。
- 使わないイベントは渡さない。壊れたイベントでも例外を投げない（標準エラーに残す）。

**窓口 port**（BLUEPRINT 3.2）
- `startAgent`：`tasks.startAgent({ agentType, name, prompt, model })`（model が空なら渡さない）、`{ agentId }` を返す。`cancelAgent`：`tasks.cancel({ id })`。`setSubagentModels(map)`：`updateSubagentSettings({ subagents: { agents: { <キー>: { model } } } })`、null で `{ subagents: null }`。`log`：`session.log(文)`。待ち時間の上限は core の側にあるので、つなぎ口にはつけない。
- `listTasks`：`type === 'agent'` だけ。`tasks.list` に親の番号がないので、`parentAgentId` は開始のイベントで覚えた値（なければ null）。`agentType` は同じそろえ方。
- `getCurrentModel`：`{ model: modelId, isAuto }`。`isAuto` は `modelId` が `auto`（前後の空白と大文字小文字は無視）。
- `listModels`：`session.rpc.model.list()` の `list` から、文字列か `id` のある要素を `{ id, name }` にする（name がなければ id）。

**試験の作り**
- 試験は、extension フォルダを一時のプラグイン（plugin.json・task.json・agents/ つき）に写し、写した adapter.mjs を偽物の SDK（fake-sdk.mjs。本物の session.js の動きに合わせた）で動かす。`tests/stage2/adapter/` に 95 件。外部の npm パッケージは使わない。終了の合図は、子のプロセス（exit-child.mjs）に本物の SIGTERM・SIGINT を送って確かめる。
- ui の直し：`ui/app.mjs` から task.json を読み直す補いと `taskPath` を消した（`GET /api/state` は、core の `setup.taskDisplays` を `taskDisplays` に写して返す。なければ空）。画面の `ABORT_DETAILS` に `extension_restarted`（エクステンションが再起動した）を足した。試験は、fake-core の `setup.taskDisplays`、server.test.mjs（app.mjs が task.json を読まない検査を1件足した）、screen.test.mjs（終わった理由の表と記号の検査に extension_restarted を足した）を直した。

## V1 の直し（本物の Copilot CLI 1.0.102 での確かめ。wip/implementation/research/V1-copilot-cli-smoke.md の不具合 2・3）

### 不具合 2【重大】ツールの処理が例外を投げると、モデルに理由が届かない
- 実機：handler が例外を投げると、モデルには「Failed to execute … due to error: Error: Tool execution failed」だけが返り、理由の文が消える。R2 の 3.3（例外の文がモデルに返る）は成り立たない。`{ textResultForLlm, resultType: 'failure' }` を返すと、文がそのまま届く（`denied` も届くが「拒まれた」の意味になる。`rejected` は手番が止まる）。
- 直し（adapter.mjs の `callTool`）：断るときは例外を投げず、`{ textResultForLlm: <理由の文>, resultType: 'failure' }` を返す。
  - core の `RecordRefusal`（`handleTool` の断り。「作業を終えてください」を含む止められた後・つながりが切れた後の文も）は、その文のまま。

  - 成功の結果は今までどおり文字列。handler は例外を投げない（`return await` で非同期の失敗も捕まえる）。`open` 以外にも handler から投げる所はない（フックと許可の受け口は元から投げない）。
