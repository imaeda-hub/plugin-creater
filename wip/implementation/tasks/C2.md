## 決めたこと

（書きながら足す。作ったファイルの状態が変わるたびに、上の状態の表も更新する）

- state.json の読み方（C1 の hearing.mjs の形）：段階は記号 `generate`、ナレッジは `kind`＝`criterion`/`other`、`status`＝`decided`、項目の日本語の名前は `itemName`。承認の時刻は `approvedAt`。日本語の名前（生成、合否の決め方、決まった）でも読めるようにした（C1 の表記が変わっても読めるように）。
- マーケットプレイスの名前（`{{marketplace_name}}`）は、プラグインの名前と同じにする（余分な決まりを作らない。名前の決まりが同じで、64文字の上限にも収まる）。インストールは `<名前>@<名前>`。
- marketplace.json は必須の項目だけ（name、owner.name、plugins[].name と source）。`owner.name` はプラグインの名前（ユーザーの名前を集めない・コミットに入れない）。`source` は `./`（リポジトリ直下のプラグイン）。
- 値の差し込みは、置く場所で書き方を変える（JSON の文字列の中、YAML のフロントマター）。説明の文に `:` や `"` があっても壊れないようにするため。

## B2 の後に合わせること（B2 のメモが空のため、BLUEPRINT 8章の名前で作っている）

- 差し込み口（`{{slot:名前}}`）：`entry-task`、`orchestrator-task`、`worker-task.<agent>`（作業エージェントごと）、`verifier-task`、`task-requirements`、`task-design`、`task-trace`、`readme-task`（BLUEPRINT 8章）。ひな形が使うものだけを必須にし、ひな形が使わない差し込み口の文が parts/slots/ にあれば、警告にする（断らない）。
- worker.agent.md を元にした worker-<名前>.agent.md では、`{{slot:worker-task}}` か `{{slot:worker-task.<どれか>}}` を `{{slot:worker-task.<その作業エージェントの名前>}}` に書き換える。フロントマターに `name:` があれば、その名前に書き換える。
- tools の作業ごとの分（manifest.json の extra_tools）の差し込み口の名前は仮：`{{orchestrator_extra_tools}}`、`{{worker_extra_tools}}`、`{{verifier_extra_tools}}`。単独の行なら `- 名前` の行に、行の途中なら `, 名前` をつないだものに置き換える。ツールがなければ、行ごと消す（行の途中なら空）。manifest に extra_tools があるのに、差し込み口がひな形にないときは断る（ツールが黙って消えないように）。B2 のメモが決まったら、名前と書き方を合わせる。
- 入口のスキルの `{{entry_skill_name}}`、`{{entry_skill_description}}`：フロントマターの `key: {{…}}` の形なら、YAML の二重引用符つきの文字列に、`"{{…}}"` の形なら、引用符の中身だけを JSON の書き方で入れる。
