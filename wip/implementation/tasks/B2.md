## 決めたこと

- フロントマターの値の差し込み口は、二重引用符の中に置く（C2 の plugin.json と同じ取り決め。中身の escape は C2）。tools の作業ごとの分は、行ごと置き換える差し込み口にした（素の字のまま置き換えても YAML が壊れず、ツールがないときは空の行が残るだけで済む。コメントの形にすると、置き換えを忘れたときに黙ってツールが抜けるので採らない）。
- 統括が作業エージェントの名前を知る手段として、決まった値 `{{worker_agents}}`（manifest.json の workers から機械的に作る一覧）を足した。統括への指示文（core の buildInstruction）に作業エージェントの名前が入らず、作業エージェントの名前を費用の低いモデルに書かせると取り違えの元になるため（creator-structure.md 3.4：AI が書く量をひな形でできるだけ減らす）。
- 作業エージェントの description は、エージェントごとに分けず、ひな形の決まった文にした（呼び名で分けると、呼び名を YAML に escape して入れる決まった値が増えるため。統括は名前で呼ぶので、description で選ばない）。割り切り：作業エージェントが2体以上のとき、`task` のエージェントの一覧では description で見分けられない。統括は `{{worker_agents}}` の一覧の名前と呼び名で呼び、メインのエージェントは呼ばない決まりなので、困らないと見た（B2 の点検 format の F-3）。
- 統括・作業・検証の description には「チャットの頼みでは呼ばない（作業は Web管理画面から始める）」を入れた。description は `task` のエージェントの一覧でメインのエージェントにも見え、メインのエージェントが直接呼ぶのを防ぐため（`disable-model-invocation: true` は `task` での起動が断られるので使えない。R1 の 6）。
- 統括の手順は、core の決まり（records.mjs）に合わせた：計画の記録を作業エージェントより先にする（作業エージェントは、開始の時点の最後の試行に数えられる。events.mjs の addToTree）。作業エージェントが何を返しても評価に進む（どの試行にも合否が付き、繰り返しが機械的に進む）。合否の記録の後に計画が断られたらまとめに進む。「作業を終えてください」と返されたら、ほかのツールを呼ばずに終える（DISCONNECTED・STOPPED・やり直しの上限・まとめの記録の後の文に共通）。
- 統括の「進められないときは止める」は書かなかった。止めると「途中で終わった」になり振り返りもされないので、分からないことは判断して試行を進め、足りなかったものをまとめと最後の返事に書く形にした（R1 の 10 の「何が足りないかを書く」を、統括では最後まで進めたうえで書く形にした）。
- 統括が `task` に書く引数の名前（`agent_type`、`mode`、`description`、`prompt`）は、設計書の出典（runtime.node の `task` の `mode` と `agent_type`）と、R2 で展開済みの 1.0.102 のパッケージの組み込みの指示の文（「Use the `task` tool with `agent_type: "research"` … Always use `mode: "sync"`」、`task` の引数の説明「3-5 word UI intent.」「Task; include complete context.」）で確かめた。
- 「スキルを使わない」は、`skill` を外して効くかが要確認（設計書 4.7、11章 #16）なので、効かないときの備え（設計書 4.7 の代わりの案）を先に入れた。害がなく、1行で済むため。
- 応答の言語：入口のスキルは「日本語で応答する。ユーザーが別の言語で書いたら、その言語で応答する」（R1 の 11）。統括・作業・検証は、ユーザーと話さず、出す文は日本語の画面に出るので「日本語で書く」とした（作業の成果物の言語は、頼みと作業ごとの指示に従う）。
