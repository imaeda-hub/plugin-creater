## 決めたこと

- 画面の部品（index.html の script と css）は、`?k=<合言葉>` を付けて読み込む。index.html の中の `%%K%%` を、サーバーが今の合言葉にして返す。画面の JavaScript は classic script（ES モジュールにしない。import は相対の場所に合言葉が引き継がれないため）。部品は `window.PluginUi`（render.js）に置き、app.js が使う。
- 合言葉はクエリの `k` だけで渡す（cookie と独自ヘッダーは使わない。img の src でも使えるため）。全応答に `Referrer-Policy: no-referrer` と `Cache-Control: no-store` も付ける。
- `startServer` の `staticDir` は、文字でも配列でもよい（配列なら前のものを先に探す）。クリエイターの画面が、自分の部品とひな形の render.js・style.css の両方を出せるようにするため（設計書 9章）。
- `routes` の関数は `(req, body)`。`req = { method, path, params, query, headers }`。値を返すと JSON、`Reply` を返すとそのまま、`HttpError(状態, 文)` を投げるとその文で断る。ほかの例外は 500 で中身を見せない。
- ファイルの窓口の確かめは `serveFile({ path, root, name })`（server.mjs）。本当の場所が root の中か、画像の種類（png・jpeg・gif・webp、拡張子は本当の場所のもの）、ほかはダウンロードの形、全部に `Content-Security-Policy: sandbox` と nosniff。
- `startApp({ core, cwd, preferredPort, taskPath })`：既定の番号は 8731。`pluginRoot` は受け取るが使わない（作業の定義は ui/ の1つ上の task.json を読む。試験用に `taskPath` で変えられる）。
- 表示の定義（displays の見出し・種類・いつ見せるか）は、状態の全体にないので、app.mjs が task.json から読み、`/api/state` の応答に `taskDisplays` として足す。core が `setup.taskDisplays` を持つなら、そちらを使う。
- 画面は、状態を1秒ごとに取り直し、版の番号が変わったときだけ描き直す。描き直しは部分ごとで、入力が前と同じ部分は触らない（止めるボタンなどの押しそこないを避ける）。畳みの開閉と入力中の設定は覚えておく。
- 受け渡しの図の強調は、フェーズで決める（実行なら作業、評価なら検証、計画なら統括。最新の試行の合否がそろっていれば最後の統括）。
- 値の形（表示の部品）：text は文字、kv は `{見出し: 値}`、table は `{columns, rows}`、progress は 0〜100 の数か `{value, max, label?}`、image と file は場所の文字列か `{ fileId, name }`。文字列は、そのままファイルの番号として `/api/files/<値>` に使う。
- 開始前の設定の送り方：`POST /api/start` の本文は `{ models: { orchestrator, worker, verifier }, maxIterations, task: { <key>: value } }`（BLUEPRINT 3.5 の `run.settings` と同じ形）。
- 色は WCAG 2.2 の 4.5:1 以上。大きさは rem。表示は明るい配色だけ（暗い配色は作らない：KISS）。
- 試験の playwright は、`import('playwright')` で見つからなければ NODE_PATH の中から探し、それでもなければ手順つきで止まる。
