## 指摘

### L-01 二つの画面を、ユーザーに話す言葉で分けていない

- 重さ：medium
- ファイルと場所：
  - make-plugin の SKILL.md「始まりの手番」の2「`plugin-creator_open` を呼び、返った URL をチャットに示す。ユーザーはこの画面で、決まったことの一覧などを見られる。」
  - references/start.md の3の示す例「使っている道具と、作業の画面で見たいことを聞く」
  - references/screen.md の問いの例「AI が作業している間に、画面で見たいことは何ですか？」「終わった後に、画面で見たい結果は何ですか？」
  - references/confirm.md の3「同じものがクリエイターの画面にも出ていると伝える。」（「クリエイター」はユーザーに話す言葉でない）
- 問題：ユーザーの前には二つの画面がある。クリエイターの画面（始まりで URL を示し、ユーザーがすでに開いている）と、できあがるプラグインの作業の画面（まだない）。words.md には後者の言葉（作業の画面（ブラウザーで開く））しかなく、前者をユーザーにどう呼ぶかが決まっていない。始まりでクリエイターの画面の URL を示した直後に、流れの説明で「作業の画面」と言い、段階「画面」では「画面で見たいこと」とだけ聞く。ユーザーが、いま開いているクリエイターの画面のことだと受け取って答え、画面の3つの項目が違う答えで済むおそれがある。
- 根拠：
  - ナレッジ communication.md「1つの言葉を2つの意味で使わない」
  - hearing.md 4.3「問いは、『なぜ聞くかの1文』と『それだけで答えられる完全な疑問文』で書く」
  - words.md「Web管理画面 → 作業の画面（ブラウザーで開く）」
  - REQ-024「説明のない専門用語を使わない」
- 直し方：
  - SKILL.md「始まりの手番」の2に、クリエイターの画面をユーザーに示すときの呼び方を1つ決めて書く。README とツールの説明の文の案（B3-tool-descriptions.md の `open`）がすでに「plugin-creator の画面」と呼んでいるので、それにそろえる（例：「plugin-creator の画面です。お話で決まったことの一覧を見られます」）。confirm.md の「クリエイターの画面」も同じ呼び方にする。words.md に行を足すのはユーザーの答え8の表を変えることになるので、足すならユーザーに確かめる。
  - start.md の示す例を「使っている道具と、できあがるプラグインの作業の画面で見たいことを聞く」にする。
  - screen.md の3つの問いの例を「できあがるプラグインの作業の画面で」に直す（例：「AI が作業している間に、できあがるプラグインの作業の画面で見たいことは何ですか？」）。開始前の設定の問いにも「作業の画面で、始める前に毎回決めたいこと」と画面を名指しする。
- 確かさ：確か

### L-02 「ここでやめて後で続ける」のおすすめの理由が、「質問しないで作って」のときに合わない

- 重さ：low
- ファイルと場所：make-plugin の SKILL.md「疲れ・急ぎ、質問しないでと頼まれたとき」の「1. ここでやめて後で続ける（おすすめ。理由：疲れていると答えがあいまいになりやすく、決まりが正しく入りにくい）」
- 問題：同じ3つの選択肢を「質問しないで作って」と頼まれたときにも使うが、おすすめの理由は「疲れていると」で始まる。疲れていないユーザーに「疲れていると」と理由を示すことになる。また「決まりが正しく入りにくい」は、何に入るかが抜けている。
- 根拠：ユーザーの答え13「聞かないと仕事の決まりが入らない理由を1文で伝え、急ぎのときと同じ3つ（ここでやめて後で続ける〔おすすめ〕／…）から選ばせる」。hearing.md 4.2 の決める質問「理由を1文添える」。憲章 第9条1項。
- 直し方：どちらの場面にも合う理由の1文にする（例：「理由：後で落ち着いて答えると、仕事の決まりがプラグインに正しく入りやすいため」）。または、場面ごとに理由を書き分ける。
- 確かさ：確か

### L-05 GitHub の URL を示されたときの問いが、手元にまだないユーザーには答えられない

- 重さ：low
- ファイルと場所：references/start.md の1「問いの例：『プラグインは手元のフォルダから読みます。GitHub から手元に取ってきたフォルダの場所を教えてください。』」
- 問題：URL だけを示したユーザーは、まだ手元にフォルダを持っていないことが多い。問いは手元にある前提で、「取ってきた」も何をすればよいか（ダウンロードするのか）が分からない。この問いだけでは答えられない。
- 根拠：hearing.md 4.3「それだけで答えられる完全な疑問文」。憲章 第9条1項。
- 直し方：「プラグインは手元のフォルダから読みます。まだ手元にないときは、GitHub からダウンロードしてフォルダに置いてください。そのフォルダの場所はどこですか？」のように、手元にないときにすることを1文足す。
- 確かさ：確か

### L-06 「実物を受け取る」の問いの例に、内部の言葉と不自然な文がある

- 重さ：low
- ファイルと場所：references/receive.md「問いの例：『実際のファイルがあると、AI が書き方や決まりを取り違えにくくなり、試験の課題にも使えるためです。最近この作業をした1回で受け取ったファイルと作ったファイル、…の場所を、パスか @ で書いてください。…』」
- 問題：
  - 「試験の課題」は内部の言葉（EVAL の課題）で、ユーザーはまだ試験の話を聞いていない。
  - なぜ聞くかの1文が「〜ためです。」で終わり、何の理由かが書かれていない（「〜ので、お聞きします」に当たる部分がない）。
  - 「最近この作業をした1回で受け取った」は、「1回」が内部の言い方（前回の1回）で、文が不自然。
  - 「パス」は説明がない。
- 根拠：words.md「EVAL → 試しに動かして採点する試験」と、表の下の「表にない内部の言葉も、説明なしに使わない」。REQ-024。hearing.md 4.3。
- 直し方：「実際のファイルがあると、AI が書き方や決まりを取り違えにくくなり、できあがるプラグインを試しに動かすときの入力にも使えます。最近この作業をしたときに受け取ったファイルと作ったファイル、いつも使っているファイル（テンプレート、手順書、スクリプトなど）は、どこにありますか？ファイルの場所（パス）か @ で書いてください。ない場合は『ない』と書いてください。」のように直す。
- 確かさ：確か

### L-08 未経験の作業の問いが、最初の一歩しか聞いていない

- 重さ：medium
- ファイルと場所：references/last-time.md の1「まだやったことがない作業だと答えたら、『初めてやるとしたら、最初に何をしますか？』と聞き、想定の1回を順に話してもらう。」
- 問題：この段で欲しいのは、想定の1回を最初から終わりまで順に話してもらうことである。しかし問いの文は「最初に何をしますか？」で、最初の一歩だけが答えになる。足りない分を聞き直す往復が増え、ユーザーが1つずつ聞かれると受け取る。
- 根拠：hearing.md 3.3「『初めてやるとしたら、最初に何をしますか？』と聞き、想定の1回を順に話してもらう」と、4.3「それだけで答えられる完全な疑問文」。問いの文が、ほしい答え（順に終わりまで）を言っていない。
- 直し方：「まだやったことのない作業でも、順番が分からないと AI は進められません。初めてやるとしたら、最初に何をして、そのあと何をしますか？終わるまでを順に書いてください。」のようにする。hearing.md 3.3 の例の文も同じに直すよう、上位の文書で直すことに挙げる。
- 確かさ：確か

### L-10 深掘りの型の例が、1つの問いで2つを聞いている

- 重さ：low
- ファイルと場所：references/deepen.md の表「判定できない合否 … 『合格だった例と、やり直しになった例を1つずつ教えてください』」と、同じファイルの「1つの問いで聞く点は1つにする。」
- 問題：同じファイルの中で、1つの問いで1つを聞く決まりと、2つの例を一度に求める問いの例が並ぶ。ユーザーが片方だけ答えることがあり、モデルがどちらに従うかもぶれる。

- 確かさ：たぶん（合格とやり直しの対を「1点」とみなすかは設計の読み方による。設計の担当に確かめる）

### L-11 決まりの確かめの続きの問いが、前の問いを見ないと分からない

- 重さ：medium
- ファイルと場所：references/rules.md「続けて聞く問いも … 書く（例：『例外を知らないと、AI はいつも同じやり方をします。どんなときに、そうしないのですか？』）」
- 問題：続きの問いは別の `ask_user` で出る。「そうしない」が何を指すかは前の問いにしかなく、この問いだけでは答えられない。費用の低いモデルは例をそのまま使うので、多くの決まりで同じ形の問いが続き、どの決まりのことか分かりにくくなる。
- 根拠：hearing.md 4.3「それだけで答えられる完全な疑問文」。SKILL.md「問いの形」の同じ決まり。
- 直し方：決まりの文を問いの中に書き直す（例：「例外を知らないと、AI はいつも同じやり方をします。『〇〇は△△にする』をしないのは、どんなときですか？」）。「違う」を選んだときの「本当はどうするか」の問いも、「『〇〇は△△にする』ではないなら、本当はどうしていますか？」のように決まりを入れる、と書き足す。
- 確かさ：確か

### L-12 「頼む場面と言い方」の問いの例が、言い方しか聞いておらず、「呼ばれる」が分かりにくい

- 根拠：REQ-015 の項目「頼む場面と言い方」。hearing.md 5.2「1つの問いで聞く点は1つにする」。REQ-024。
- 直し方：問いの例を2つにする（「どんなときに頼むかが分からないと、できあがるプラグインが動き出さないことがあります。この作業は、どんなときに頼みますか？」と「頼むときの言葉が分からないと、できあがるプラグインが動き出さないことがあります。この作業を頼むとき、どんな言葉で頼みますか？」）。
- 確かさ：確か
