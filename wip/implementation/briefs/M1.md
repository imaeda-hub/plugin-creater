# ひな形を移す（M1）

あなたは、Agent Plugin（GitHub Copilot CLI 向け）に精通したハーネスエンジニアで、生成プラグインのひな形の置き場所を移す担当である。

## 受け取るもの

- 共通の決まり：`wip/implementation/briefs/common.md`（全部守る。作業のメモは `wip/implementation/tasks/M1.md`）。
- ユーザーの決定（RESUME.md の答え25）：ひな形を `skills/make-plugin/assets/template/` から、クリエイターの直下の `template/` に移す。理由：Copilot CLI はスキルを読むたびに、スキルのフォルダの全ファイルの名前を「Related files」としてモデルに足す。ひな形が入っていると、make-plugin を読むたびに、使わない80件あまりのファイル名が届く。
- 移してよいことの確かめ：`wip/implementation/research/V1-copilot-cli-smoke.md` の7.1（`template/` の中のスキル・エージェント・エクステンション・MCP・plugin.json・marketplace.json は、どれも読み込まれない。直す場所の一覧もある）。

## やること

1. `git mv skills/make-plugin/assets/template template` で移す（中身は変えない。`assets/` が空になれば消す）。
2. ひな形の場所を参照している所を、全部探して直す。`grep` で `assets/template`、`assets', 'template'`、`assets/`、`template` などを、クリエイターの全体（`skills/`、`com.github.copilot/`、`tests/creator/`、`tests/dev-eval/`〔heldout を除く〕、README、`.github/`、`plugin.json`）で探す。少なくとも次がある：
   - `skills/make-plugin/scripts/scaffold.py`（`DEFAULT_TEMPLATE` と冒頭の説明。スクリプトの場所から見た相対の位置で探す）。
   - `com.github.copilot/extensions/plugin-creator/screen.mjs` など、クリエイターのエクステンションがひな形を読む所。
   - `skills/make-plugin/SKILL.md` の54〜55行目、`references/confirm.md` の24行目、`references/generate.md` の35行目。
   - `tests/creator/`（check_creator.py、scaffold・extension の試験の補助）、`tests/dev-eval/convert.py`・`test_convert.py`（変換で写さないものの決まりなど）。
   - クリエイターの README のフォルダの説明（あれば）。
3. SKILL.md・references は自然言語の実装資産で、エージェントの振る舞いを直接決める。直すのは、ひな形の場所の書き方だけにする。
   - SKILL.md 54行目の「自分では読まない。読むとコンテキストウィンドウが早く埋まるためである」は、移した後も、メインのエージェントがひな形を読まないための決まりとして要るかを判断する。モデルが場所を知らなければ読みに行かないなら、行を短くするか消してよい。
   - ひな形の場所を AI に示す必要がある所（confirm.md の task.schema.json、generate.md の作業エージェントに渡す絶対パス）は、「Base directory for this skill」のフォルダから見た位置（`../../template/`）で書く。または組み立てのスクリプトやエクステンションが絶対パスを返す形にする。どちらが確かかは、今の手順の流れを読んで決める。
   - SKILL.md の本文は500行・5,000トークン以内（tiktoken o200k_base）、references はそれぞれ20,000バイト未満を守る。直した後に数えて、メモに書く。
4. あわせて、`references/generate.md` の27〜28行目の manifest の形にある `"orchestrator": { "extra_tools": [] }` を消す。統括エージェントの定義から tools: をなくしたため（答え24）。scaffold.py は空なら受けるので、消しても動く。
5. 試験を全部通す：`tests/creator/`（check_creator.py、scaffold、extension、test-plugin）、ひな形の `tests/run.py`（組み立てた生成プラグインで）、ひな形の1段目の自己試験と2段目、`tests/dev-eval/`（convert・personas・runner）。check_creator.py の REQ-037（会話例がない）の1件の不合格は、前からのもの。
6. `wip/implementation/BLUEPRINT.md` の0章・1章のフォルダの配置の記述を、新しい場所に直す（BLUEPRINT は統括の文書だが、今回は直してよい）。

## 書かないこと

- 設計書・仕様書・README の「上位の文書」で、場所を説明している所（creator-structure.md、generated-plugin-structure.md など）は直さない。メモの「上位の文書で直すこと」に、ファイルと行と直し方を書く。
- ひな形の中身は変えない。

## 終わったら

コミットして push する（ブランチ claude/multi-agent-implementation-rules-7pfoww。コミットの末尾は、統括から渡される Co-Authored-By と Claude-Session の行）。最後の返事で、直したファイルの一覧、SKILL.md・references で直した文、試験の結果、上位の文書で直すことを返す。
