## つなぎ口がすること
- プラグインの根を `import.meta.url` から求め、plugin.json の name を読む（ツール名の頭）。土台のファイルは、どの生成プラグインでも中身が同じになるようにする（BLUEPRINT 2章）。
- `joinSession` で、core.toolDefinitions のツール（名前は `<名前>_<短い名前>`、skipPermission: true）、フック（onPreToolUse → core.preToolUse。同期で例外を投げない。拒むときの返り値の形は R2）、許可の求めの受け口（onPermissionRequest：core.onPermissionRequest に渡し、いつも { kind: 'no-result' } を返す。例外を投げない）を登録する。
- セッションのイベントを、中立のイベント（BLUEPRINT 3.1）に直して core.onEvent に渡す。A1 の求め：agent.started の agentType は `<プラグイン>:<エージェント>` の形にそろえる、tool.started に arguments を付ける、許可の求めの detail に sandboxPermissive（`requestSandboxPermissive`）を付け、detail.sandboxBypass は `requestSandboxBypass && !requestSandboxPermissive` にする。エクステンション自身の権限の求め（extension-permission-access、extension-env-access）も、種類が分かるように渡す（画面に出さないのは core が決める）。
- port（BLUEPRINT 3.2）を session.rpc で作る：tasks.startAgent・cancel・list、tools.updateSubagentSettings、model.getCurrent、選べるモデルの一覧は session.rpc.model.list()（R2 の (2) #2。返り値の形が決まっていないので、id と name を取り出せる要素だけを使う）、session.log。
- createCore に、セッションの番号、作業フォルダ、COPILOT_HOME（R2 のやり方）、記録の置き場所（<COPILOT_HOME>/plugin-data/<名前>/runs/）、startUi: (core) => startApp({ core, cwd }) を渡す。
- Copilot CLI の終了で終わる（R2 の起動と終了。画面のサーバーは同じプロセス）。終わるときに core.shutdown を呼ぶ。

## 試験
- 偽物の SDK のセッションで、イベントの直し方、ツールの登録（名前、skipPermission）、フックが例外を投げないこと、許可の求めの受け口がいつも no-result を返し例外を投げないこと、port の呼び出しの形を確かめる。
- core と ui の試験が引き続き通ること（`node --test "skills/make-plugin/assets/template/tests/stage2/core/*.test.mjs"` など）。
