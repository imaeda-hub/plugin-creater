# 最後の報告の材料をまとめる（R5）

あなたは、Agent Plugin（GitHub Copilot CLI 向け）に精通したハーネスエンジニアで、実装の途中で溜まった「上位の文書で直すこと」と「最終確認で人が確かめること」を、1つにまとめる担当である。ファイルは直さず、まとめのファイルだけを書く。

## 読むもの

- `wip/implementation/RESUME.md`：「報告すること」「ユーザーの答え」（1〜30）「後の仕事に渡すこと」「次にすること」と、エージェントの表の括弧の中。
- `wip/implementation/tasks/*.md`：各担当の「上位の文書で直すこと」「要確認」「実機でしか確かめられないこと」「最終確認」の節（「X の直し」「X4 の直し」「V1 の直し」の節を含む）。
- `wip/implementation/reviews/X3-triage.md` の4章（C の文の一覧）。
- `wip/implementation/research/V1-copilot-cli-smoke.md`（とくに6節「確かめられなかったこと」と9節）、`R1`〜`R4` の報告の「設計書と食い違う」などの節。
- 照らし合わせのため：`docs/specs/*.md`、`docs/design/*.md`、`docs/constitution/constitution.md`。今の文書にすでに直っている（統括が直した仕様書 REQ-023・REQ-004 など）ものは除く。

`tests/dev-eval/heldout/` は読まない（git の出力も `grep -v heldout` で外す）。

## 書くもの

`wip/implementation/REPORT-draft.md`。冒頭に「状態：途中／完了」。途中で止まっても続けられるよう、節ごとに書き足す。

1. **上位の文書で直すこと**：文書ごと（憲章、仕様書の各ファイル、設計書の各ファイル、ナレッジ `.claude/memory/` の各ファイル）に、節の番号と、直す中身を1件1行で並べる。同じ中身の重なりは1件にまとめ、出どころ（RESUME の答えの番号、担当の番号）を括弧で添える。もう当たらなくなったもの（後の直しで実装が変わり、元の指摘の前提がなくなったもの）は、今の実装を見て確かめ、除くか、今の形に書き直す。
2. **ユーザーの判断で決まったこと**：答え1〜30のうち、上位の文書に入れる必要があるものを、どの文書のどの節に入れるかと合わせて並べる（1と重なってよいが、決定の一覧として別に置く）。
3. **最終確認で人が確かめること**：本物の Copilot CLI のログイン済みのアカウント、Windows・macOS、実ブラウザー、GitHub への公開の後など、開発の環境では確かめられなかったこと。1件ごとに、何を、どう確かめるか（手順を短く）、確かめられなかった理由。重なりはまとめる。
4. **残っていること**：実装の残り（たとえば EVAL の目安の値、会話例）と、その理由。
5. **気づいたこと**：上のどれにも入らない、設計者に知らせるべきこと（たとえば、利用枠の上限の経過、開発の環境の準備〔bubblewrap と socat をセットアップのスクリプトに足すこと〕、`/home-gen-a/` を消してもらうこと、GitHub のリポジトリの名前の変更）。

## 書き方

読む人は、設計者（ユーザー）である。憲章 第9条（分かりやすさ）に従い、番号や記号だけで示さず、中身を言葉で書く。ユーザーと話すときの決まり（RESUME の節）のとおり、設計書と憲章の用語をそのまま使い、言い換えや比喩を使わない。

## 終わったら

`wip/implementation/REPORT-draft.md` だけをコミットして push する（`wip/implementation/briefs/common.md` の決まり）。最後の返事で、節ごとの件数を返す。
