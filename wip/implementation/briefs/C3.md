## eval.mjs
- estimate：回数と AI クレジットの見込み（testing.md 8.2 のかけ算。前に EVAL をした記録があればその値、なければ目安。目安の値がまだないことは、出力で分かる形にする）。
- run：testing.md 10.4 のとおり。生成プラグインあり（--plugin-dir、COPILOT_PLUGIN_DIR_ONLY=true、requestExtensions: true）となしで、課題ごとに回数分、まっさらな作業フォルダで実行する。onUserInputRequest は決まった返事。onPermissionRequest は、作業フォルダの外への書き込みを拒み、ほかは許可し、managedApprovalRequired（R2 の読み方）は EVAL を止めて理由を示し、extension-permission-access は許可する。利用の上限はクレジットを足さずに止める。ありのときは、チャットに出た URL を Playwright で開き、課題の設定を入れて開始し、終わった理由が出たら結果を読む。なしのときは session.idle で終わる。イベントを記録に残す（10.4 の表）。採点は生成プラグインの外で行い、検証エージェントの合否を使わない。
- R2 の (2) #4（ユーザーの ~/.copilot/extensions/ のエクステンションも読み込まれる見込み）：読み込まれたエクステンションを記録し（R2 にある session.rpc.extensions.list() など）、生成プラグイン以外のエクステンションがあれば、結果に「ほかのエクステンションが混ざった」と示す。止める手段が R2 で確かめられるなら使う。確かめられなければ、作業のメモに「要確認」と書く。
- 結果：実行ごとの基準ごとの合否、あり・なしの点数とその差、使った AI クレジット（assistant.usage の totalNanoAiu の合計。1クレジット＝10億 nano-AIU）を、<生成プラグイン>/tests/results/eval-<日時>/ に JSON で書き、標準出力にも出す。

## 採点
- check.type（program の採点のしかた）を、最小限の種類で決める（ファイルがある、決まった言葉がある、正規表現に合う、など）。決めた種類と形を作業のメモの「作業エージェントへの引き継ぎ」に書く（作業エージェントが eval.json を書くときに使う）。
- model の採点：基準の文と成果物を渡して合否と理由を返す判定の関数を、引数で受ける形にする（ユーザーの試験では Copilot SDK のセッション、開発の試験では Agent SDK）。

## 試験
- 偽物の SDK（クライアントとセッションとイベント）で、許可の求めの答え方の決まり、利用の上限で止まること、見込みのかけ算、結果の形、program の採点を確かめる。本物の Copilot CLI とモデルは使わない（最終確認で人が確かめる。testing.md 9章）。
