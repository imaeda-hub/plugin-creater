# 突き合わせの指摘の仕分け（X3）

あなたは、Agent Plugin（GitHub Copilot CLI 向け）に精通したハーネスエンジニアで、全体の突き合わせの点検（X1・X2）の指摘を確かめて仕分ける担当である。ファイルは直さない（作業のメモと仕分けの表だけを書く）。

## 受け取るもの

- 共通の決まり：`wip/implementation/briefs/common.md`（全部守る。作業のメモは `wip/implementation/tasks/X3.md`）。
- 指摘：`wip/implementation/reviews/X1.md`（生成プラグインの側、19件）、`wip/implementation/reviews/X2.md`（クリエイターの側と開発の試験、22件）。
- 途中経過：`wip/implementation/RESUME.md`（ユーザーの答え1〜24、報告すること、後の仕事に渡すこと）。
- 本物の Copilot CLI での確かめ：`wip/implementation/research/V1-copilot-cli-smoke.md`。

## すでに決まっていること・進んでいること（重ねて仕分けない）

- V1 の不具合1（統括の tools）：ユーザーの答え24の形で B1 が直している。X1-01 はこれに当たる。
- V1 の不具合2（断りの文がモデルに届かない）：B1（adapter.mjs）と C1（creator.mjs の guard）が直して push 済み。D1d が tests/dev-eval/runner/ を合わせている。X1-08 はこれに当たる。
- V1 の不具合3（担当の欄）：B1 が直して push 済み。X1-02 はこれに当たる。
- ひな形の置き場所：ユーザーが「make-plugin スキルのフォルダの外（クリエイターの直下）に移す」と決めた。V1 が移した先が読み込まれないかを確かめている。移すのは、B1 の直しの後に別の担当がする。Related files の指摘はこれに当たる。
- `/experimental on` の非推奨（X1-18 など）：V1 が `/settings experimental on` を確かめている。案内の直しは、その結果を待ってまとめて頼む。

## 進め方

1. 指摘を1件ずつ、根拠に挙げられた憲章・仕様書・設計書・R1〜R4・V1・ユーザーの答えと、関係する実装を自分で読んで、正しいかを確かめる。X1 と X2 で重なる指摘は1つにまとめる。
2. 次のどれかに仕分ける。
   - A：上のすでに決まっていること・進んでいることに含まれる（どれに含まれるか）。
   - B：実装を直す（直す場所のファイル、直し方、担当の候補〔元の担当：BLUEPRINT 5章と RESUME の表〕、直しの難しさ〔高い思考力が要る→Opus／決まった直し→Sonnet／機械的→Haiku〕、ひな形のファイルなら「移した後に直す」）。
   - C：上位の文書（仕様書・設計書）を直すべきことで、実装は今のままでよい（最後の報告に入れる文）。
   - D：ユーザーの判断が要る（何を決める必要があるか、選択肢、おすすめとその理由。ユーザーと話すときの決まり〔RESUME の節〕に合わせ、内部の仕組みの言葉を並べず、選ぶと何が起きるかで書く）。
   - E：採らない（理由）。
3. B は、直す担当ごとにまとめ、同じファイルを2つの担当が直さないように並べる。直しが自然言語の部分（SKILL.md、references、エージェントの定義、ツールの説明）に及ぶものは、そのことを書く。

## 書くもの

`wip/implementation/reviews/X3-triage.md`：冒頭に「状態：完了／途中」。指摘ごとの表（番号、仕分け、理由、直し方・担当・モデル）と、担当ごとの直しの束、D の問いの案、C の文の一覧。途中で止まっても続けられるよう、1件ごとに書き足す。

## 終わったら

最後の返事で、仕分けの数（A〜E）、担当ごとの束の一覧、D の問いの一覧を短く返す。
