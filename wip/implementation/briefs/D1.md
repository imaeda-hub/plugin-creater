# D1 の指示：開発の試験の EVAL

開発の試験（testing.md 1章：AI が Claude Code で行う。Copilot CLI は動かさない）の EVAL の仕組みを作る。4つの担当に分ける。担当の番号は D1a〜D1d。どの担当も、testing.md の 1〜9章、11.1 を全部読む。ナレッジ .claude/memory/agent-sdk-eval.md、user-simulation.md、claude-plugin-eval.md と、R4（wip/implementation/research/R4-prototype-reuse.md。試作のどれを、どう直して使うか）を読む。試作は origin/claude/test-prototype の prototype/ にある（`git show origin/claude/test-prototype:prototype/<パス>`）。

置き場所は tests/dev-eval/ の下。Node.js の部品は tests/dev-eval/package.json で版を固定する（@anthropic-ai/claude-agent-sdk は Claude Code と同じ版にそろえる。R4 の版。playwright は 1.56.1）。node_modules は git に入れない。Python の部品（docx・xlsx を作るなど）は、スクラッチの仮想環境で使う。

## D1a：Claude Code 向けの変換（tests/dev-eval/convert.py と試験）
- testing.md 4章の表と決まりのとおり、Copilot CLI 向けのプラグイン（クリエイター自身、または生成プラグイン）を、Claude Code が読み込める形に置き換える。試作の convert.py を、R4 の直しのとおり直して使う（model のリストのとき、モデルを ID に固定、エクステンションのツール名の置き換え、会話例を外す、置き換えの直後に `claude plugin validate`）。
- モデルの対応の表：claude-haiku-5.5 → claude-haiku-5-5、gpt-6-luna → claude-haiku-5-5、claude-sonnet-5.5 → claude-sonnet-5-5、gpt-6.1-sol → claude-sonnet-5-5（Copilot の価格表で同じ値段）、claude-opus-5.5 → claude-opus-5-5。`model` のないエージェントは `model: inherit`。
- エクステンションは外し、エクステンションのツール名（エージェントの定義の tools と、本文のバッククォートの名前）を、EVAL の仕組みが出す MCP のツール名（`mcp__<サーバー名>__<ツール名>`）に置き換える。サーバー名は D1c・D1d と合わせる（作業のメモに書く）。
- B2 の引き継ぎ：統括の本文の task の引数の名前（agent_type、mode）は Claude Code の Agent の引数と違う。どう扱うかを決めて作業のメモに書く（推測で Claude Code の引数を書かない。Claude Code の公式ドキュメントで確かめる）。
- 試験：クリエイター自身と、C2 の組み立ての見本（tests/creator/scaffold/）で作った生成プラグインを置き換え、`claude plugin validate` に通ること。置き換えの各規則。

## D1b：模擬ユーザー（tests/dev-eval/personas/ と、模擬ユーザーの形の決まり）
- ユーザーの決定（RESUME.md のユーザーの答え20）：試作の2人（週報、議事録。prototype/tools/personas/）を直して使い、まだやったことのない作業でファイルのない1人を新しく作る。見ない模擬ユーザーは H1 が別に作るので、作らない。
- 模擬ユーザーの形を決め、tests/dev-eval/personas/FORMAT.md に書く（H1 がこの形で作る）。testing.md 6.1 のとおり：依頼の内容、ナレッジごとの答える条件と自分から話すか、示すファイル（docx か xlsx を1つ以上。本当の決まり、例外のある決まり、たまたまの書き方を1つずつ入れる）、ファイルの決まりへの答え（決まりの確かめの4つの答えのどれを選ぶか）、ナレッジごとの「聞いたか」を見る言葉、内側の EVAL の課題と採点基準（testing.md 7章。模擬ユーザーごとに、クリエイターとは別に用意する）、話し方（6.3 の5種）。
- 週報の模擬ユーザーに、話し方の5種（口数が少ない、あいまいに答える、「分からない」と答えがち、「特にない」と答えがち、急いでいる）を用意する。
- docx・xlsx は、スクラッチの仮想環境の python-docx・openpyxl で作り、作るスクリプトも置く。
- 試験：形の決まりに合うかを確かめる小さなスクリプト（D1c が読み込むときにも使う）。

## D1c：外側の EVAL とユーザー役（tests/dev-eval/runner/ の外側の部分）
- 試作の lib.mjs・outer.mjs・test_user_role.mjs を、R4 の直しのとおり直して使う。Agent SDK の隔離（testing.md 5章、ナレッジ agent-sdk-eval.md）。サンドボックスの道具（bubblewrap、socat）がこの環境にあるかを確かめ、なければ作業のメモに書く（入れるのは統括がユーザーに聞く）。
- クリエイターのエクステンションの置き換え（testing.md 4章）：C1 の com.github.copilot/extensions/plugin-creator/ の、SDK に依らないモジュール（creator.mjs など）を読み込み、ツールを Agent SDK の同じプロセスの MCP サーバーとして出す。問答の記録は、自分の会話の記録から qa.jsonl と同じ形で作る。起票は偽物の gh で受けて記録だけ残す。
- ユーザー役（testing.md 6.1、6.2）：モデルは ID で固定する（claude-sonnet-5-5）。ユーザー役の試験（6.2 の7つの観点）。
- 外側の EVAL の流れ（3章の手順2〜3、6.5 の採点、6.6 の記録の全文）。対照のクリエイター（6.3。大まかな質問しかしないクリエイター。試作の control-creator を直す）。
- 会話例の作成のスクリプト（6.6。A3 の決まり：冒頭30行に「クリエイターの版：x.y.z」）。examples/ に書く。
- 見ない模擬ユーザー：tests/dev-eval/heldout/ を、実行のときに読み込む作りにする。中身は読まない（common.md）。形は D1b の FORMAT.md。
- 実際のモデルは使わない試験（偽物の Agent SDK の応答で流れを確かめる）だけを作る。本物のモデルで EVAL を回すのは、統括がユーザーの承認をとってから。

## D1d：内側の EVAL（tests/dev-eval/runner/ の内側の部分）
- 生成プラグインの中心の処理と画面を、Agent SDK 用のつなぎ口で動かす（testing.md 4章の後半：画面を開くツールと記録のツールを同じプロセスの MCP サーバーとして出す、統括を別の Agent SDK の実行で始める、作業・検証のモデルを画面で選んだものにする、止めるで統括の実行を中断、状態はフックとメッセージから）。core の窓口（BLUEPRINT 3.2）と中立のイベント（3.1）に合わせる。B1 の adapter.mjs が手本になる。
- 人と同じ流れで Playwright で画面を操作する（testing.md 7章）。C3 の skills/test-plugin/scripts/screen.mjs を使い回せるなら使う。
- 採点は C3 の grade.mjs を使い、モデルの判定は Agent SDK で行う（testing.md 10.5）。プラグインあり・なしの比べ合い。
- 実際のモデルは使わない試験だけを作る。
