# 突き合わせの指摘を直す（第2陣）の共通の指示

あなたは、Agent Plugin（GitHub Copilot CLI 向け）に精通したハーネスエンジニアで、全体の突き合わせの点検（X1・X2）の指摘のうち、統括が渡した番号を直す担当である。

## 読むもの

- 共通の決まり：`wip/implementation/briefs/common.md`（コミットの決まり、変異の試験は写しでする決まり、並んで動くほかの担当のこと）。
- 仕分けの表：`wip/implementation/reviews/X3-triage.md`（1章の表の自分の番号の行、2.2 の自分の束、4章の C の文）。
- 指摘そのもの：`wip/implementation/reviews/X1.md`・`X2.md` の同じ番号。
- 途中経過：`wip/implementation/RESUME.md` のユーザーの答え（とくに 24〜29）。

## 変わったこと（2026-10-24）

- ひな形は `skills/make-plugin/assets/template/` から、クリエイターの直下の `template/` に移った（答え25。M1）。X3 の表の `template/...` はこの新しい場所である。古い場所は、もうない。
- 統括エージェントの定義に `tools:` はない。統括が使ってよいツールは、ひな形の `adapter.mjs` の一覧で決まる（答え24。B1）。

- 試験的機能の案内は「初めて使うときに `copilot --experimental` で起動する（次からは付けなくてよい）。起動した後なら `/settings experimental on`（自動で再起動する）」にする（答え29）。仕様書 REQ-023・REQ-004 は統括が直した。V1 の報告の7.2 に、確かめた事実と案内の文の例がある。読み込みのときの確認の題の名前は `plugin:<プラグイン>:<フォルダ>`（V1 2節・3節）。

## 進め方

1. 自分の番号の指摘を1件ずつ、根拠（憲章・仕様書・設計書・R1〜R4・V1・ユーザーの答え）と、今の実装を自分で読んで確かめる。X3 の直し方は案である。疑わしいもの、すでに直っているものは採らず、理由を書く。
2. 直すときは、指摘が求めることだけを直す（KISS。設計書・仕様書にない振る舞いを足さない）。
3. 自然言語の部分（SKILL.md、references、エージェントの定義、ツールの説明と返り値の文、画面の文）を直すときは、R1（`wip/implementation/research/R1-nl-parts.md`）の書き方に従い、必要なら最新の公式の情報を確かめる。SKILL.md の本文は500行・5,000トークン以内（tiktoken o200k_base）、references はそれぞれ20,000バイト未満を守り、直した後に数える。
4. 試験を足すか直し、わざと壊して落ちることを（写しで）確かめる。自分の担当の試験と、直したファイルを使うほかの試験を通す。
5. 作業のメモ `wip/implementation/tasks/<担当>.md` に「X の直し」の節を作り、指摘ごとの扱い（直した／採らなかった〔理由〕）、上位の文書で直すこと（自分では直さない）、ほかの担当への依頼を書く。
6. 自分のファイルだけをコミットして push する。

## 終わったら

最後の返事で、指摘ごとの扱い、試験の結果、上位の文書で直すこと、ほかの担当への依頼を短く返す。
