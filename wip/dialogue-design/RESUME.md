## 終わった調査の要点（D・E）

- 状態は会話の外のファイルに残すのが各社共通の勧め。会話の圧縮は細部を落とす。Copilot CLI 1.0.98 は、圧縮の後に「前に使ったスキルは、使う前にもう一度読み込む」旨の文字列を持つ。
- 「聞くか進めるか」の既定はモデルで逆向き。Copilot CLI 自体のプロンプトに「行動に偏れ」「100語以内」がある。聞き取りのスキルは「質問が仕事で、答えを待つ」と明記する必要がある（考察）。
- `ask_user` は 1.0.98 でフォーム形式（選択肢＋自由回答、推奨は default）。`--no-ask-user` と自律モードでの挙動は資料が食い違い、実機で要確認。
- 質問の形は流派が割れる（superpowers は自由回答を先に、Spec Kit clarify は推奨を先頭に1問ずつ5問まで）。決着した証拠はない。
- 質問の前に、読めるものを読み、調べて分かることは聞かない流れが新しい道具ほど強い。
- 失敗は両方向：聞かない（質問ゼロで「あいまいさなし」）、あいまいな同意を許可と扱う、番号やラベルだけで質問する。
- 安いモデルは「共有理解まで質問する」を数問に潰しやすい。手順を途中までしか守らないと、スキルなしより悪いという研究がある。
- サブエージェントは「調べる・抽出する・点検する」に使い、ユーザーへの質問は親が持つのが共通。

## A（Copilot CLI）の要点（偽物のモデルで実際に動かして確かめた）

- `ask_user` は2つの版がある。対話の画面はフォームの版（1回に複数の項目、自由入力は常にでき、推奨は `default`）。SDK の既定は古い版で、EVAL では `askUserVariant: "elicitation"` が要る。
- Ctrl+D（断る）と autopilot では「ユーザーは不在なので自分で判断して進めよ」が自動で返る。`-p` と `--no-ask-user` ではツール自体がない。
- サブエージェントは `ask_user` を持たない（tools に書いても入らない）。渡した prompt しか見えず、最後の文だけが返る。並列にできる。
- スキルの本文は会話の履歴（呼ばれた直後の `<skill-context>`）に入る。`references/` はパスだけで、モデルが読む。圧縮の後も最後に呼ばれたスキルの本文は残る。
- 圧縮は入力の上限の約80%で始まる。圧縮の後に原文で残るのは、ユーザーが打ったメッセージ、要約、最後のスキル、todo だけ。**`ask_user` の答えは要約にしか残らない。** そのため、聞き取りの結果は会話の外（ファイルや記録のツール）に残す必要がある。
- `--resume`／`--continue` で、履歴、セッションのフォルダ（files/、plan.md）、セッションの SQL の表が戻る。`/clear` は新しいセッションになる。
- `@ファイル` は中身ではなくパスと行数だけを入れる。view は 20KB を超えるファイルを読まない。
- システムプロンプトはモデルで違う（gpt-4.1 などに「あいまいでも進めよ」、gpt-5.5 に「追加の質問をしない」）。
- 聞き取りの手本は plan モードの指示（範囲・振る舞い・方法を ask_user で確かめ、手番は必ず ask_user で終える）。原文は `A-appendix-3-builtin-prompts.md`。

## C（LLM が聞き手になる研究）の要点

- 聞かれないと話さない模擬ユーザーに、素の LLM は弱い（ReqElicitGym：7 モデルで最高 0.32）。終える判断もモデルでばらばら。網羅の骨組み、その場のメモ、記録係と点検係の分離が効いたという報告がある（模擬ユーザー・小規模）。
- 「〜という決まりですか？」のような確認の質問は「はい」に偏る。LLM のユーザー役は逆に「いいえ」に偏るので、外側の EVAL ではこの偏りを測れない。
- 長い会話の劣化（平均39%低下）は、前の情報を毎回見せ直すと一部戻る。状態を記録して見せ直す設計の根拠。
- 公開されたインタビュアーのプロンプトどうしで、聞き直し方、要約を返すか、選択肢を出すかが食い違う。比べた実験は見つからなかった。
