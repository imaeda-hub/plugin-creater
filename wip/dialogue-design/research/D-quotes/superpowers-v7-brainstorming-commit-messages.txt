* feat(antigravity): native plugin manifest for the Antigravity Marketplace

Add .antigravity-plugin/plugin.json with the Marketplace fields
(displayName, logo, suggestedPrompts, version, author), a logo rendered
from the Superpowers mark by scripts/render-antigravity-logo.sh, and a
.version-bump.json entry. The Codex sync excludes the manifest and logo.

With the native manifest, agy installs Superpowers as an Antigravity
plugin. Before, `agy plugin install <repo>` fell back to importing the
repo as a Gemini CLI extension and rejected the copied Claude-format hooks
file on every session.

Superpowers bootstraps through skill discovery: agy lists each installed
skill's description, and using-superpowers' "Use when starting any
conversation" gets the model to load it. agy has no session-start hook
event; a rules/ file would also load in Cursor, which reads plugin rules
from the same repo root; a PreInvocation hook runs on every model call.
Verified on agy 1.3.1 (Gemini 3.8 Flash) across 15 clean sessions:
brainstorming or systematic-debugging loads before any code.

* brainstorming: ask which technology choices they want to make

A session asked to design an iOS app never discussed platform or stack and
built a web app with a home-screen icon. Brainstorming now finds out early
which technology choices the person wants to make and which they're
handing over: talk it through with a technical partner, pick sensible
defaults and say them plainly for someone who isn't, and base defaults on
an existing project's stack. The Red Flags row on sensible defaults now
says to state them rather than avoid them.

* brainstorming: generalize technology guidance to how it gets made

Non-software projects (a painting, a cake) need the same move: find out
which medium, tools, materials and resources they want to choose, which
they're handing over, and what they already have. Software keeps its
examples: platform, programming language, libraries.
