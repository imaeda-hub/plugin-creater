# クリエイター憲章

- 版：0.8.0（ドラフト）

## 第1章 総則

### 第1条 目的

本憲章は、クリエイターの開発・保守と、生成プラグインの生成において守る最上位ルールである。

### 第2条 憲章の体系

| 憲章 | 適用対象 |
| --- | --- |
| クリエイター憲章（本文書） | クリエイター |
| 生成プラグイン憲章 | 生成プラグイン |

## 第2章 共通条項

### 第C1条 用語

| 用語 | 定義 |
| --- | --- |
| クリエイター | リポジトリ plugin-creater 自身。Agent Plugin を生成するプラグインである |
| 生成プラグイン | クリエイターが生成した Agent Plugin |

### 第C2条 準拠仕様

1. Agent Plugins 1.0.0 と GitHub Copilot CLI の公式プラグイン仕様に従う。
2. 両仕様が両立しない場合は Agent Plugins 1.0.0 を優先する。

### 第C3条 成果物

1. 成果物は、憲章・仕様書・設計書・実装資産（ソースコード、テストコード、`SKILL.md` などの定義ファイル）とする。
2. 優先順位は 憲章 ＞ 仕様書 ＞ 設計書 ＞ 実装資産 とし、下位は上位に矛盾しない。
3. 仕様書の要件は、設計書・実装資産・テストまで追跡できるようにする。

### 第C4条 開発の進め方

ユーザーと対話しながら、憲章 → 仕様書 → 設計書 → 実装資産 の順に開発・保守する。開発途中のユーザーの意見や判断を成果物に反映する。

### 第C5条 SWEBOK

SWEBOK の知識体系・考え方を踏まえて開発する。一律の手順とはせず、対象に適した実践方法を選ぶ。

### 第C6条 自己改善

1. 自身の改善につながる課題を見つけたら、自身の GitHub リポジトリに Issue を起票する。
2. 起票は毎回ユーザーの承認を得てから行う。

## 第3章 クリエイター固有条項

### 第P1条 生成プラグインの要件

1. 生成プラグインは、生成プラグイン憲章を満たす。
2. 生成時に、生成プラグイン憲章の第2章にクリエイター憲章の第2章（共通条項）の本文を書き写す。

### 第P2条 生成の進め方

1. 生成プラグインも、第C4条の順序でユーザーと対話しながら作成する。
2. 生成プラグイン憲章の第2〜4章は変更しない。プラグイン固有の条項は第5章に追加する。

### 第P3条 生成後の保守

生成プラグインの保守は生成プラグイン自身が行う。

### 第P4条 テンプレートの管理

テンプレートの改訂は、以後に生成する生成プラグインにだけ適用する。

### 第P5条 改訂

本憲章の改訂はユーザーの承認を得て行い、版と変更履歴を更新する。
