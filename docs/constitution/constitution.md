# クリエイター憲章

- 版：0.20.0（ドラフト）

> 最大の目的：ユーザーとの対話を通じてユーザーのナレッジを引き出し、それを組み込んだ、公式仕様に準拠した Agent Plugin を生成する。

## 第1章 総則

### 第1条 目的

本憲章は、クリエイターが守る最上位ルールであり、クリエイターが生成する生成プラグインが守るルールも定める。

### 第2条 構成

| 章 | 適用対象 |
| --- | --- |
| 第2章 共通条項 | クリエイターと生成プラグイン |
| 第3章 クリエイターの条項 | クリエイター |
| 第4章 生成プラグインの条項 | 生成プラグイン |

### 第3条 用語

| 用語 | 定義 |
| --- | --- |
| クリエイター | リポジトリ plugin-creater 自身。Agent Plugin を生成するプラグインである |
| 生成プラグイン | クリエイターが生成した Agent Plugin |
| 統括エージェント | 作業全体の指揮とタスク分担を行う |
| 作業エージェント | 割り当てられた作業を実行する |
| 検証エージェント | 作業成果物を検証する |
| Web管理画面 | ローカルWebサーバーが提供する、設定・監視・確認のためのブラウザ画面 |
| PDSサイクル | Plan（計画）– Do（実行）– Study（評価・学習）の反復 |

### 第4条 クリエイターのインプットとアウトプット

| 区分 | 内容 |
| --- | --- |
| インプット | ユーザーからのプロンプトと、対話で引き出したユーザーのナレッジ |
| アウトプット | 生成プラグイン |

## 第2章 共通条項

### 第5条 準拠仕様

1. Agent Plugins 1.0.0 と GitHub Copilot CLI の公式プラグイン仕様に従う。
2. 両仕様が両立しない場合は Agent Plugins 1.0.0 を優先する。

### 第6条 リポジトリの構成

1. リポジトリは、次の4種類の成果物を基本とする。

   | 成果物 | 内容 |
   | --- | --- |
   | 憲章 | プロジェクトが必ず守る最上位ルール |
   | 仕様書 | 実現する機能や振る舞いの要件 |
   | 設計書 | 仕様を実現するための構造・方式 |
   | 実装資産 | プログラムのソースコードとテストコードに加え、`SKILL.md` などのエージェント用定義ファイルを含む |

2. 優先順位は 憲章 ＞ 仕様書 ＞ 設計書 ＞ 実装資産 とし、下位は上位に矛盾しない。
3. 仕様書の要件は、設計書・実装資産・テストまで追跡できるようにする。

### 第7条 開発の進め方

ユーザーと対話しながら、憲章 → 仕様書 → 設計書 → 実装資産 の順に開発・保守する。

### 第8条 SWEBOK

[SWEBOK](https://www.computer.org/education/bodies-of-knowledge/software-engineering) の知識体系・考え方を踏まえて開発する。一律の手順とはせず、対象に適した実践方法を選ぶ。

### 第9条 分かりやすさ

1. 人間に伝える内容と人間が読む成果物は、分かりやすさを何より重視し、簡潔に、伝わる用語で書く。
2. 人間の指摘は、文言をそのまま残さず、目的に沿って直す。

### 第10条 KISS

1. 必要なものだけを、できるだけ単純に作る（KISS：Keep It Simple, Stupid）。
2. リポジトリを肥大化させない。

## 第3章 クリエイターの条項

### 第11条 生成プラグインの要件

生成プラグインは、第2章と第4章を満たす。

### 第12条 既存資産の流用

1. 生成プラグインは、必ずしも一から作らない。ユーザーは、生成プラグインに組み込む資産をすでに持っていることがある。
2. ユーザーとの対話を通じて、既存の資産がないかを確認し、引き出す。
3. 既存の資産があるものは流用し、ないものだけを新たに作る。

## 第4章 生成プラグインの条項

### 第13条 マルチエージェント構成

1. 統括エージェント1体、作業エージェント1体以上、検証エージェント1体で構成する。
2. 作業エージェントは自らの成果物を判定しない。検証エージェントは成果物を修正せず、指摘を統括エージェントに返す。

### 第14条 Web管理画面

1. ローカルWebサーバーを起動し、Web管理画面で各種設定を行えるようにする。
2. 既定ではローカルホストからの接続だけを受け付ける。

### 第15条 監視

Web管理画面で、各エージェントの状態・担当タスク・PDS のフェーズを監視でき、実行を停止できるようにする。

### 第16条 結果確認

Web管理画面で、各エージェントの実行結果と検証結果を確認できるようにする。

### 第17条 PDSサイクル

PDS サイクルで成果物と作業の進め方を改善する。

- Plan：統括エージェントが実施内容と評価基準を決める。
- Do：作業エージェントが計画に沿って試行する。
- Study：検証エージェントが結果を分析し、統括エージェントが次の試行に反映する。

### 第18条 自己改善

1. 実行中にログを残し、実行後にログを振り返って課題を洗い出す。
2. 自身の改善につながる課題を見つけたら、自身の GitHub リポジトリに Issue を起票する。
3. 起票は毎回ユーザーの承認を得てから行う。
