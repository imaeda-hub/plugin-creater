# 仕様書の書き方

## 置き場所とファイルの分け方

- 仕様書は `docs/specs/` に置く。
- 仕様書はすべてクリエイターの仕様書である。
- クリエイターの機能ごとにファイルを分ける。クリエイターが出力する生成プラグインの要件も、機能の1つとして扱う。

## 要件の番号

- 要件には、すべての仕様書を通した通し番号を付ける（例：`REQ-001`）。

## 要件の書き方

1つの要件は、次の3つで書く。

| 項目 | 内容 |
| --- | --- |
| 要件 | 満たすべきこと |
| 根拠 | 要件のもとになった憲章の条項。具体化に使ったナレッジや公式仕様があれば、あわせて書く |
| 受け入れ基準 | 要件を満たしたと判断できる条件 |

例：

```markdown
### REQ-006 接続の制限

- 要件：Web管理画面は、最初の設定では、生成プラグインを動かしているマシンのブラウザーからしか開けない。
- 根拠：憲章 第20条2項
- 受け入れ基準：
  - 最初の設定で、同じマシンのブラウザーからは開ける。
  - 最初の設定で、ほかのマシンからは開けない。
```
