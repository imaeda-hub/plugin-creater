# 段階「項目の点検」

目的：10項目の聞き漏らしをなくす。この段階の始めに `plugin-creator_state` を呼び、返り値の「聞くことの状態」と「確かめたいこと（仕事のやり方や決まりのうち、状態が「候補」のもの）」を見る。

## 進め方

10項目を、下の表の順に1つずつ見る。

- その項目のナレッジや候補が記録にあれば、分かったことを示し、違うところと足りないところを聞く（理解の確かめ）。この聞き方も、その項目を聞いたことに数える。示した候補は、答えに合わせて「決まった」か「外した」にする。
- 記録になければ、具体的に聞く（聞き出す問い）。答えがあいまいなら、`references/deepen.md` の型で聞き直す。
- 作り直しで、段階「決まりの確かめ」で確かめた元のプラグインの決まり（「このとおり」か「そうしないときもある」と答えたもの）がある項目は、聞き直さない。「聞いた」にし、決まりの確かめでの答えの抜き書きを添える。できていたこと（「〇〇と頼むと、〇〇をする」）は、この数に入れず、1つ目の点のとおりに示して確かめる。
- 答えを受けたら、`plugin-creator_record` でナレッジにし、`plugin-creator_progress` で項目を「聞いた」「決まりなし」「保留」のどれかにする。抜き書きを添える。

| 項目 | 問いの例（記録にないとき） |
| --- | --- |
| 作業の目的 | 「目的が分からないと、AI は何を優先すればよいか決められません。この作業は、何のためにしていますか？」 |
| 頼む場面と言い方 | 2つの問いで聞く。「どんなときに頼むかが分からないと、できあがるプラグインが動き出さないことがあります。この作業は、どんなときに頼みますか？」の後に「頼むときの言葉が分からないと、できあがるプラグインが動き出さないことがあります。この作業を頼むとき、どんな言葉で頼みますか？」 |
| 受け取るもの | 「何を受け取るかが分からないと、AI は違うものを読んだり、足りないまま始めたりします。この作業を始めるとき、何を受け取りますか？」 |
| 進め方 | 「手順が分からないと、AI は自分で手順を決めてしまいます。この作業は、どんな順で進めますか？」 |
| 成果物 | 「最後に作るものの形が分からないと、AI は違う形で作ります。この作業で最後に作るもの（成果物）は、何ですか？」 |
| 合否の決め方 | 「合格の条件が分からないと、AI は出来の良し悪しを決められません。できあがったものが合格かどうかは、どこを見て決めますか？」 |
| 決まった書き方やルール | 「決まった書き方を知らないと、AI は自分の好みで書きます。この作業で決まっている書き方やルールは、何ですか？」 |
| 守らないと困ること | 「守るべきことを知らないと、AI がそれを破り、取り返しのつかないことになるおそれがあります。この作業で、守らないと困ることは何ですか？」 |
| 使う道具と環境 | 「使う道具が分からないと、AI は作業を進められません。この作業では、何を使って作業しますか？」 |
| いつもと違うとき | 「いつもと違うときの扱いを知らないと、AI はそのまま進めて間違えます。いつもと違うことが起きた1回を思い出して、何が起きて、どうしたかを教えてください。」 |

- 合否の決め方は、成果物の何を見て、何なら合格かまで聞く。答えはナレッジの種類「合否の決め方」にする。
- 目的、合否の決め方、守らないと困ること、いつもと違うとき、好みは、記録から推し量れても、示して確かめる（赤信号の表の1行目）。

## 区切りの要約

10項目に未着手がなくなったら、記録した内容を短く要約して示し、違うところと足りないところを聞く（理解の確かめ）。推し量ったことと、保留の項目は、そうと分かるように書く。同じことを繰り返して書かない。
