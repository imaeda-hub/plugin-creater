# 質問の改善案

目的：自分の質問の足りなかったところを洗い出し、plugin-creator の GitHub リポジトリに出す Issue（改善の要望）の案を示す。質問は、使った結果をもとに直し続けるためである。make-plugin（生成の後）と test-plugin（頼まれた試験の後）の両方で使う。

## 見るもの

| とき | 見るもの |
| --- | --- |
| 生成の後 | 1. `plugin-creator_state` を「振り返りの材料」つきで呼び、返った「質問の改善案の対象のナレッジ」を見る（その項目を聞いた後にユーザーが自分から話したものと、生成前の確認で足したもの）。<br>2. 同じ返り値の問答の記録のすべてを読み、聞き直しが続いた問いと、「分からない」と答えた問いを探す。<br>3. 試験で不合格になった原因のうち、ナレッジが足りなかったもの |
| 頼まれた試験の後 | 次の2つだけで見る。<br>1. 試験で不合格になった原因のうち、ナレッジが足りなかったもの（試験の結果と、生成プラグインの `tests/knowledge.json` で見る）<br>2. ユーザーが生成プラグインを直した内容のうち、ヒアリングで聞いていれば入ったもの（`git -C <生成プラグインのフォルダ> diff plugin-creator-generated` で見る。この印がなければ、最初のコミットからの差分で見る） |

## 案の書き方

- 決まった言葉だけで書く。Issue は公開のリポジトリに載ることがあるためである。
  - 書くもの：段階と項目の名前、起きたことの種類、数、問いの形（選択肢か自由入力か）、クリエイターの版、対話のモデル
  - 書かないもの：問いの文、答え、ナレッジの文、ファイル名。問いの文にも、仕事の分野の言葉が入りうるためである。
- 起きたことの種類は、次のどれかにする：「聞いた後にユーザーが自分から話した」「生成前の確認で足された」「聞き直しが続いた」「『分からない』と答えた」「試験の不合格の原因がナレッジの不足だった」「ユーザーの直しが、聞いていれば入るものだった」
- 1回の振り返りで、項目ごとに1件にまとめ、重要な順に並べる。
- クリエイターの版は、plugin-creator の `plugin.json`（`skills` フォルダの1つ上）の version である。対話のモデルは、今の会話のモデルの名前である。
- 案の例：
  - 題：「項目の点検：合否の決め方で、聞いた後にユーザーが自分から話したナレッジが2件」
  - 本文：「段階：項目の点検／項目：合否の決め方／起きたこと：聞いた後にユーザーが自分から話した（2件）／問いの形：自由入力／クリエイターの版：（版）／対話のモデル：（モデルの名前）」

## 示し方と起票

- 見つからなかったときは、質問の改善案がないことを1行で示して終える。
- 案はチャットで示し、案ごとに、起票してよいかを聞く（承認の問い。選択肢は「起票しない」「起票する」の順。おすすめを付けない）。
- 起票すると答えた案だけ、`plugin-creator_issue` に題と本文を渡す。このとき Copilot CLI がツールの許可の確認を出すことを、先に伝える。起票しないと答えた案は起票しない。
- gh がない、またはログインしていないと返ったときは、返った入れ方とログインのしかたを示す。
