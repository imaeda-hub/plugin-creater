# 段階「資産と公開のプラグイン」

目的：できあがるプラグインで流用するものを決める。すでにあるものを使うと、一から作るより間違いが少なく、作る量も減るためである。

## 1. ユーザーの資産

- 資産の候補を一覧にして示す。候補は、段階「読む」で記録したもの（作り直しでは、元のプラグインの流用できる部品も）と、前回の1回の話に出たファイルと道具である。
- 理解の確かめの問いで、使わないものと、ほかに使っているものを書いてもらう。
- 問いの例：「すでにあるものを使うと、AI が一から作るより間違いが少なくなります。次のものは、できあがるプラグインで使う予定です。（一覧）使わないものと、ほかにこの作業で使っているファイルや道具を書いてください。なければ「ない」と書いてください。」
- 記録：`plugin-creator_record` の資産で、使うものを「流用する」、使わないものを「流用しない」にする。足されたものは、場所も聞いて記録する。`plugin-creator_progress` で項目「資産」を「聞いた」にし、答えの抜き書きを添える。
- 作り直しでは、元のプラグインの部品（スクリプト、MCP サーバーなど）のうち、作り直した後も使えるものは、作り直さずに流用する。

## 2. 標準機能と公開のプラグイン

- 作業の一部が、Copilot CLI の標準機能か、公開のプラグインで済まないかを、自分で調べる。ユーザーには断らない。
  - 標準機能：Copilot CLI の組み込みのコマンドとツール。公式のコマンドリファレンス（https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference）で確かめる。
  - 公開のプラグイン：Awesome Copilot など。Copilot CLI に最初から登録されているマーケットプレイス awesome-copilot は、`copilot plugin marketplace browse awesome-copilot` で一覧を見られる。
- 使えるものがあれば、1つずつ、決める問いで使うかを聞く。何に使えて、何が足りないかを短く示す。候補が4つを超えるときは、一覧を示し、使うものを自由入力で書いてもらう。
  - 問いの例：「（プラグインの名前）を使うと、（何の部分）を作らずに済みます。この部分に、（プラグインの名前）を使いますか？」選択肢は「使う（おすすめ）」「使わない（できあがるプラグインの中に作る）」のように、理由に合うほうを先頭にしておすすめにする。
- 使うと選んだ部分は、できあがるプラグインの中に作らない。
- 使えるものが見つからなかったときも、調べた結果を短く示し、ほかに使っているプラグインや Copilot CLI の機能がないかを聞く（聞き出す問い）。
- 記録：`plugin-creator_record` の標準機能と公開のプラグインに、名前、種類、選んだ結果、使う部分を書く。`plugin-creator_progress` で項目「標準機能と公開のプラグイン」を「聞いた」にし、答えの抜き書きを添える。
