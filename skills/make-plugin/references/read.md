# 段階「読む」

目的：示されたファイル（作り直しでは元のプラグイン）から、決まりの候補、前回の1回の手がかり、資産の候補を取り出して記録する。この段階の問いは、読めなかった PDF をテキストにしてもらう問いだけである。

## 読ませ方

- ファイルは自分で読まず、読み取り役に読ませる。読んだ中身が会話に残ると、以後の往復のたびに送り直され、コンテキストウィンドウが早く埋まるためである。
- 読み取り役は、`task` ツールでエージェント `plugin-creator:reader` に頼む。読み取り役は渡した文しか見えないので、次をすべて書く。
  - ファイルの絶対パス（作り直しでは、元のプラグインのフォルダの絶対パス）
  - 分かっている作業と目的
  - 探すもの：決まりの候補、前回の1回の手がかり、流用できる資産の候補。作り直しでは、できていたこと（何を頼むと、何をするか）と、流用できる部品（スクリプト、MCP サーバーなど）も
- ファイルが多いときは、いくつかに分けて、並べて頼んでよい。
- 例外：ユーザーが打った発言に文書がそのまま添えられて届いたとき（発言に「The user included native document attachments in this message.」の文が加わる）は、その文書は自分で読んで候補を記録する。もう会話に入っているので、読み取り役に回しても小さくならないためである。

## 返ったものの記録

返ったものは、すぐに記録する。ツールの結果は、コンパクションで消えるためである。

| 返ったもの | 記録のしかた |
| --- | --- |
| 決まりの候補 | `plugin-creator_record` のナレッジ。状態は「候補」、出どころは「ファイルから読んで確かめた」（作り直しの元からは「既存のプラグインから読んで確かめた」）、ユーザーの言葉の欄にはファイル名と箇所と短い引用、項目は10項目のうち当てはまるもの。状態は、確かめた後に「決まった」か「外した」にする |
| できていたこと（作り直し） | 決まりの候補と同じくナレッジの候補にする。文は「〇〇と頼むと、〇〇をする」の形で書く（決まりの候補と見分けるため）。項目は、頼む場面と言い方、進め方、成果物のうち当てはまるもの。段階「できていたことの確認」で確かめる |
| 資産の候補、流用できる部品 | `plugin-creator_record` の流用する資産の候補 |
| 前回の1回の手がかり | 記録せず、段階「前回の1回」で、話と食い違うところを聞くのに使う |
| 読めなかったファイル | ユーザーに、読めなかったファイルと理由を示す |

- PDF が読めなかったときは、自由入力の欄で、テキストにしてもらう（PDF の文の貼り付けか、テキストのファイルの場所）。テキストのファイルなら読み取り役に読ませ、貼り付けなら、もう会話に入っているので自分で読んで候補を記録する。

## 次へ

- 作り直しなら、段階を「できていたことの確認」に進める。
- そうでなければ、段階を「前回の1回」に進める。
