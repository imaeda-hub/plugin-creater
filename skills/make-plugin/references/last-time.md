# 段階「前回の1回」

目的：最近実際にやった1回を、最初から順に話してもらう。本人が当たり前だと思っている手順や決まりは、項目ごとの問いでは話されにくいためである。この段階の始めに `references/deepen.md` も読む。

## 進め方

1. 最近実際にやった1回を、最初から終わりまで順に話してもらう（聞き出す問い）。話の途中で口を挟まない。
   - 問いの例：「AI は、あなたがふだん当たり前にしている手順を知りません。最近この作業を実際にした1回を思い出して、最初にしたことから終わるまでを、順に書いてください。」
   - まだやったことがない作業だと答えたら、「初めてやるとしたら、最初に何をしますか？」と聞き、想定の1回を順に話してもらう。この後の進め方は同じである。
2. 話を番号付きの短い時系列にして示し、違うところと足りないところを聞く（理解の確かめ）。
3. 時系列の抜けと、判断が要った段だけを、`references/deepen.md` の型で聞く。
4. 段階「読む」の候補と食い違うところは、その場で聞く（問いの例：「ファイルでは A、前回は B でした。普段はどちらですか？」）。
5. 話に出た手順や決まりのうち、まだ聞いていないものは、その場で聞く。
6. 最後に、「初めての人がやると、どこで間違えそうですか？」を1回聞く。
7. 記録した内容を短く要約して示し、違うところと足りないところを聞く（理解の確かめ）。推し量ったことは、推し量ったと書く。同じことを繰り返して書かない。

## 記録

- 分かった決まりは、そのつど `plugin-creator_record` でナレッジにする。状態は「決まった」、出どころは「ヒアリングの答え」、項目は10項目のうち当てはまるもの。
- 10項目の状態は、この段階では変えない。段階「項目の点検」で、分かったことを示して確かめる。
- 1の答えを受けたら、`plugin-creator_progress` で項目「前回の1回」を「聞いた」にし、答えの抜き書きを添える。
- 話の中身は、試験の課題とその入力のファイルの元にもなる（`references/confirm.md`）。

## 次へ

- ファイルから読んだ候補を記録していれば、段階を「決まりの確かめ」に進め、`references/rules.md` を読む。
- そうでなければ、段階を「項目の点検」に進め、`references/items.md` を読む。
