# test-plugin

このスキルの仕事は、plugin-creator で作ったプラグイン（生成プラグイン）を、ファイルの形の検査、動きの試験、試しに動かして採点する試験（EVAL）の3段階で試験し、結果を示すことである。

## 決まり

次の決まりは、このスキルの終わりまで有効である。

1. 道具を入れる前と、EVAL を始める前には、`ask_user` でユーザーの承認を得る。答えを受け取るまで、入れない・始めない。道具はユーザーのパソコンを変え、EVAL は AI クレジットを使うためである。
2. 承認の問いは、おすすめを付けず、よいと答える選択肢を最初に置かない。Enter だけで先頭の選択肢が選ばれるためである。問いの文は、なぜ聞くかの1文と、それだけで答えられる疑問文で書く。
3. 日本語で応答する。ユーザーが別の言語で書いたら、その言語で応答する。
4. ユーザーに話す言葉は、`<スキルのフォルダ>/../make-plugin/references/words.md` の表に従う。説明のない内部の言葉は、ユーザーに伝わらないためである。
5. `<スキルのフォルダ>` は、このスキルを呼んだときに示される「Base directory for this skill」のフォルダの絶対パスである。スクリプトは、ここからの絶対パスで動かす。作業フォルダは、スキルのフォルダではないためである。
6. 試験の合否は、スクリプトの結果で決める。自分では合否を決めない。

## 手順

1. `ask_user` と `plugin-creator_open` があるかを確かめる。ないものがあれば、「始められないとき・答えが来ないとき」のとおりにして止まる。
2. `plugin-creator_open` を呼び、返った URL をチャットに示す。試験の結果は、この画面でも見られる。
3. 試験する生成プラグインのフォルダを決める。頼みや会話から分からなければ、自由入力の欄で聞く（問いの例：「どのプラグインを試験するかが分からないと、始められません。試験するプラグインのフォルダの場所を書いてください。」）。
4. 道具を確かめる：`python3 <スキルのフォルダ>/scripts/check_tools.py --plugin <生成プラグインのフォルダ>`。
   - 足りない道具があれば、その道具と、入れ方と、入れる場所を示し、入れてよいかを聞く。選択肢は「入れない」「入れてよい」の順にする。
   - よいと答えたら、`--install` を付けて動かす。入れないと答えたら、その道具が要る試験ができないことを示して止まる。
   - Python や Node.js そのものがないときは、入れ方を示して止まる。
5. ファイルの形の検査と動きの試験：`python3 <生成プラグインのフォルダ>/tests/run.py`。段階ごとの合否と、不合格の試験とその理由を示す。不合格でも、ここでは直さない。
6. EVAL の見込み：`node <スキルのフォルダ>/scripts/eval.mjs estimate --plugin <生成プラグインのフォルダ> --runs 3` で、実行の回数と、使う AI クレジットの見込みを出す。
   - 回数と見込みを示し、始めてよいかを聞く。見込みは上限ではないことも伝える。選択肢は「EVAL をしない」「回数を変える」「この回数と見込みで始める」の順にする。
   - 回数を変えると答えたら、回数を自由入力の欄で聞き、見込みを出し直して、もう一度聞く。
   - しないと答えたら、7を飛ばして8に進む。
7. EVAL：`node <スキルのフォルダ>/scripts/eval.mjs run --plugin <生成プラグインのフォルダ> --runs <回数>`。結果は `<生成プラグインのフォルダ>/tests/results/eval-<日時>/` に書かれる。途中で止まったときは、返った理由を示す。
8. 結果を示す：5の段階ごとの合否と、EVAL をしたときは、実行ごとの基準ごとの合否、生成プラグインあり・なしの点数とその差、使った AI クレジット。`plugin-creator_results` に結果のファイルの場所（`tests/results/latest.json` と、EVAL の結果のファイル）を渡し、クリエイターの画面に出す。
9. 質問の改善案：`<スキルのフォルダ>/../make-plugin/references/improve.md` を読み、「頼まれた試験の後」のとおりに示す。

## 始められないとき・答えが来ないとき

- `ask_user` がないとき（`-p` や `--no-ask-user` で起動したとき）：`-p` と `--no-ask-user` を付けずに、対話モードで起動し直すよう文章で示して止まる。承認を得られないためである。
- `plugin-creator_open` がないとき：次をすべて示して止まる。
  - `/experimental on` で有効にして、Copilot CLI を起動し直す。
  - Copilot CLI を起動し直し、plugin-creator の読み込みのときの確認で「Yes」か「Yes, and always allow」（このフォルダでは常に許可）を選ぶ。
  - `/extensions mode` が Disabled なら、Load & Augment に戻す。
- `ask_user` の結果が「User cancelled the request.」か「The user is not available to respond」で始まる文のときは、答えが来なかったとして扱う。
  - 承認がなかったとして、道具を入れず、EVAL を始めない。
  - 何を聞きたかったかと、続け方（チャットに答えを書く。autopilot で動かしているなら、autopilot を切る）を短く示して止まる。
  - `task_complete` があれば、それを呼んで止まる。続けるよう促されても、承認なしに進めない。
